# CLI, API, SDK, вебхуки — когда пользователь фичи разработчик

Пользователь — разработчик, часто в спешке, иногда ночью при инциденте. Он читает сообщения об
ошибках внимательнее всех и встраивает инструмент в скрипты и автоматизацию, где его никто не
видит. Главная метрика — сколько времени от знакомства до первого успешного вызова, и сколько
времени уходит на разбор ошибки.

## Командная строка (CLI)

- Справка по каждой команде с примерами; самые частые сценарии — в начале справки.
- Ошибка говорит, что не так и как исправить, с примером правильной команды; опечатка в команде —
  предложение похожей.
- Коды завершения: ноль при успехе, не ноль при ошибке — скрипты на этом держатся.
- Данные — в стандартный вывод, сообщения и прогресс — в поток ошибок; машиночитаемый вывод
  (например, JSON) — по флагу.
- В неинтерактивном запуске (скрипт, CI) — никаких вопросов, которые подвесят выполнение; флаг
  «согласен» для подтверждений.
- Опасные операции — пробный прогон без изменений и подтверждение, которое в скрипте заменяется
  флагом.
- Прогресс для долгих операций; прерывание по Ctrl+C оставляет систему в понятном состоянии.
- Цвет и оформление отключаются, когда вывод идёт не в терминал или человек это попросил.
- Порядок источников настроек (флаг, переменная окружения, файл конфигурации) — понятный и
  описанный.

## API

- Единый формат ошибок во всём API: стабильный машиночитаемый код, человекочитаемое описание,
  поле с ошибкой для ошибок ввода. Для HTTP есть стандартный формат описания проблемы — сверить с
  актуальным стандартом.
- Ошибки ввода перечисляют все проблемные поля сразу, а не по одной.
- Повтор запроса безопасен: операции, создающие что-то или списывающие деньги, принимают ключ
  повтора, по которому сервер узнаёт дубль.
- Ограничение частоты: в ответе видно, сколько осталось и когда можно повторить.
- Большие списки — постранично, способом, который не ломается, если данные меняются между
  запросами.
- Версии и устаревание: как клиент узнаёт, что метод будет убран, и сколько времени у него есть.
- Долгие операции — асинхронно: принять, вернуть идентификатор, дать узнать статус или прислать
  результат.

## SDK

- Первый успешный вызов — несколько строк кода из документации, которые работают при копировании.
- Ошибки SDK — с тем же кодом и описанием, что в API, плюс подсказка.
- Значения по умолчанию разумные (таймауты, повторы — явно описанные и настраиваемые).

## Вебхуки

- Подпись, по которой получатель проверяет отправителя.
- Повторная доставка при сбое у получателя: сколько раз, с какими паузами; получатель должен
  спокойно переживать дубли и нарушенный порядок.
- Журнал доставок и ручной повтор для разработчика.
- Тестовая отправка из кабинета.

## Частые ошибки

- «Error: something went wrong» без кода и без причины.
- Команда, которая в CI ждёт ответа «y» и висит до таймаута.
- Повтор запроса создаёт дубль заказа.
- Несовместимое изменение API без предупреждения и без версии.

## Платформенные детали — где брать

Соглашения конкретного языка и экосистемы, формат описания API, стандарты HTTP — профильный скилл
или актуальная документация и стандарты.
